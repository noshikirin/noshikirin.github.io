# Repository instructions

## Issues

Use `.github/ISSUE_TEMPLATE/work.md` when creating an issue, including through
the CLI or API. Fill in the applicable sections. Add exactly one of the `epic`,
`story`, or `bug` labels, and add stories as sub-issues of their epic. Report
anything you could not set through the available tools.

## Pull requests

Use `.github/PULL_REQUEST_TEMPLATE.md` when creating or updating a PR
description, including through the CLI or API. Keep the description accurate as
the diff changes. Describe the checks actually performed and what remains
untested. Complete the privacy check honestly; never tick a box you did not verify.

Use `Closes #N` only when the PR completes the referenced issue. Otherwise,
reference the issue without a closing keyword and describe the remaining work.
